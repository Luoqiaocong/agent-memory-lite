# agent-memory-lite

一个轻量、克制的对话 Agent 长期记忆系统，探索如何在**不依赖重量级外部设施、不引入额外后台大模型开销**的前提下，让对话助手拥有清晰可控、可演化的长期记忆能力。

## 这个项目想实现什么

- **自然延续对话上下文**：跨轮次、跨会话记住用户的客观背景、偏好、技能与忌口，让回答自然贴合个人情况，而不是每次从零开始。
- **可追踪的记忆生命周期**：每一条记忆都不只是静态文本，而是具备完整生命周期的原子事实——支持**新增写入、重复提及加固、单值变更覆盖、多值精准替换与主动遗忘**。
- **克制且低成本的设计**：相比每轮对话后额外再调用一次总结/合并大模型，本项目更倾向用结构化约束与明确的边界规则，把记忆更新收敛到一次自然的对话工具调用中完成。

## 核心设计思考

1. **单值自动覆盖 vs 多值按 ID 精准替换**
   - **单值事实**（如所在地、姓名、职业）：同一维度同一时间只保留最新状态，新值写入时自动停用旧值，并记录上一次变更前的值。
   - **多值事实**（如爱好、技能、饮食忌口）：如果依赖模型复述旧值做文本匹配，极易因少字或同义词导致替换失败；因此检索记忆时直接透出记录 ID，模型在一次调用中填入 `replace_id` 即可精准替换旧记忆，彻底避免“先遗忘再保存”的两步割裂。
   - **主动遗忘**：仅当用户彻底放弃某项多值偏好且无新值替代时，才触发遗忘软删除。

2. **软删除与上下文克制**
   - 被覆盖或遗忘的记忆默认保留在历史记录中而非物理抹除；重复被提及的记忆会自动累加提及权重。
   - 注入日常对话的上下文始终保持精简（当前有效事实 + 最近一次前任值），避免把冗长的历史迁移链全塞进提示词干扰模型判断。

3. **先跑通、再按真实反馈演进**
   - 不过度在前期为假想中的极端边缘场景堆砌复杂防御，而是通过真实对话运行与核心单元测试验证主链路，遇到实际问题再逐步补齐。

## 演进历程

- **`v0.1.0`｜最小可用原型（MVP）**
  验证“结构化事实记忆”的核心想法：从零跑通基础记忆的提取、落库、单值覆盖与对话上下文拼装。

- **`v0.2.0`｜对话自主驱动记忆读写**
  放弃独立、死板的后台抽取流程，将记忆查询与写入交给对话中的 Agent 自主触发，让记忆动作自然融入多轮交互。

- **`v0.3.0`｜分层重构与生命周期完善**
  理顺数据模型、仓储操作与业务编排的职责边界；引入频次加固、排序权重与跨库通用事务，让记忆读写不再散落各处。

- **`v0.4.0`｜主动遗忘与单次多值替换闭环**
  - **主动遗忘**：补齐记忆生命周期的“删除”一环，支持用户明确放弃或推翻旧事实时进行软删除，避免过时信息持续污染后续回答；
  - **单次多值替换**：透出记录 ID 并引入 `replace_id`，将修改多值记忆由“先删再存两次调用”收敛为单次写入/替换动作；
  - **边界收敛与测试基线**：理顺业务层与数据层的模型边界、简化核心写入分支，并建立覆盖核心记忆流转与工具入参解析的自动化测试基线。

- **`v0.5.0`｜记忆自动注入与按需历史追溯**
  - **动态上下文自动注入**：基于运行时上下文将最新长期记忆实时注入系统提示词，免去每轮开局主动查库的延迟与漏查风险；
  - **按需历史轨迹查询**：支持追溯单类记忆（含已停用旧记录）的完整演变历程，在保持日常上下文精简的同时解决连续变更后早期历史不可见的问题；
  - **测试完善**：补充中间件注入与历史查询单元测试，覆盖完整记忆流转链路。
